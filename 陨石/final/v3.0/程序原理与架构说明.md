# 陆地陨石撞击模拟器 v3.0 — 程序原理与架构说明

> 对应代码：`陨石/final/v3.0`（Flask 版）与仓库根目录 `demo.html`（独立 JS 版）
> 代码基线：`bef2c92`（含 391da35 的当量口径调整）
> 读者对象：想理解模型假设、改参数、做二次开发或写论文/答辩材料的人

---

## 0. 一句话概括

程序把「一颗陨石以给定直径、材质、速度、角度进入大气」这件事，拆成
**大气减速烧蚀 → 空爆/地撞判定 → 坑径/冲击波/热辐射/等级** 四段，
每一段用一个简化的工程公式求解，最后交给前端画轨迹与灾害范围、交给模板库生成文字叙事。

它追求的是**量级正确、参数可解释、单文件可运行**，不是高精度数值模拟。

## 3. 总体架构

### 3.1 分层

```
┌──────────────────────────────────────────────────────────┐
│ 表现层  templates/index.html（canvas 2D + 面板 + 动画）    │
└───────────────▲──────────────────────────┬───────────────┘
                │ JSON result              │ POST /api/simulate
┌───────────────┴──────────────────────────▼───────────────┐
│ 服务层  appV2.0.py（路由 / 模板匹配 / 叙事 / 问答 / 解析） │
└───────────────▲──────────────────────────┬───────────────┘
                │ dict result              │ params dict
┌───────────────┴──────────────────────────▼───────────────┐
│ 编排层  simulation.py（唯一入口 run_simulation）           │
└───────────────▲──────────────────────────────────────────┘
                │ 分步调用
┌───────────────┴──────────────────────────────────────────┐
│ 物理层  trajectory → breakup → crater/shockwave/thermal    │
│         → classify                                        │
└──────────────────────────────────────────────────────────┘
```

### 3.2 一次模拟的调用链

```
POST /api/simulate
  └─ 参数校验（材质、5–50000 m、1–100 km/s、5–90°；target 强制陆地）
     └─ simulation.run_simulation(params)
        1. meteoroid.compute_mass / compute_kinetic_energy      → 初始质量、动能、TNT
        2. trajectory.integrate_trajectory(dt=0.01, sample_every=50)
             └─ 时间步循环：密度 → 阻力/重力 → 烧蚀 → 解体 → 高度 → 采样
        3. breakup.determine_mode(traj)                          → 空爆/地撞、当量、爆高
        4. crater.compute_crater(...)                            → 坑径
        5. shockwave.compute_shockwave(release, ground_eff)      → 三档超压半径
        6. thermal.compute_thermal(release, ground_eff)          → 火球、烧伤半径
        7. classify.classify_disaster(release_tnt)               → L1–L5
        8. classify.observer_damage(distance, shock, thermal)    → 观测点结论
     └─ 返回 dict（input_echo / initial / trajectory / mode / release /
                   crater / shockwave / thermal / disaster_level / observer_damage）
  └─ 前端 renderResults() 填卡片；setupAnimation() 用 trajectory.samples 做动画
  └─ 可选：/api/ai/* 用同一份 result 生成文字
```

## 4. 物理模型逐模块

### 4.1 初始量（`meteoroid.py`）

球体假设：

```
r = D / 2
m0 = (4/3)·π·r³·ρ_body
E0 = ½·m0·v0²            （v0 单位换算成 m/s）
TNT[t] = E0 / 4.184e9
```

材质参数（`constants.MATERIALS`）：

| 材质 | 密度 kg/m³ | 强度 σ Pa | 说明 |
|---|---|---|---|
| 冰彗星 | 1000 | 1.0e6 | 疏松，最易解体 |
| 岩石陨石 | 3000 | 5.0e6 | 普通球粒陨石 |
| 铁陨石 | 7800 | 2.0e8 | 致密，穿透性强 |

### 4.2 大气密度（`atmosphere.py`）

五层分段指数模型，层间密度连续：

```
ρ(h) = ρ_base · exp(−(h − h_base)/H)
```

| 层 | 底界 | 标高 H | 用途 |
|---|---|---|---|
| 对流层 | 0 km | 8 500 m | 低层稠密大气 |
| 平流层 | 12 km | 6 710 m | 20–50 km |
| 中间层 | 50 km | 7 240 m | 烧蚀主区间 |
| 热层 | 85 km | 11 060 m | 稀薄但路径长 |
| 外逸层 | 600 km | 50 000 m | 本程序起点 200 km 在此层 |

标定锚点：12 km→0.312、50 km→1.03e-3、85 km→8.2e-6、200 km→2.5e-10 kg/m³。
不建模风场、纬度、季节、太阳活动。

### 4.3 轨迹积分（`trajectory.py`，核心）

**状态量**：高度 h、速度分量 v_x / v_y、质量 m、时间 t。

**控制方程**（沿速度反方向减速，重力只作用于垂直分量，v_y 向下为正）：

```
阻力：   a_drag = ½·ρ(h)·v²·C_D·A / m
         dv_x = −a_drag·(v_x/v)·dt
         dv_y = (−a_drag·(v_y/v) + g(h))·dt
重力：   g(h) = g0·(R/(R+h))²
烧蚀：   dm/dt = −½·ρ·v³·C_H·A / Q_abl      （仅 v > 3 km/s）
高度：   dh/dt = −v_y
几何：   A = π·r(m)²·pancake_mult
```

- 质量减少时半径按 `r = (3m/4πρ)^(1/3)` 收缩，A 随之减小；
- 弹道倾角由 `atan2(v_y, v_x)` 动态更新，减速时水平分量衰减更快、弹道变陡——这是轨迹弯曲的来源；
- **解体（pancake）**：当动压 `q = ½ρv² ≥ σ` 时触发一次，`A` 瞬间 ×5，阻力与烧蚀同步放大；用 `breakup_triggered` 标志保证只触发一次。

**终止条件**（满足其一）：

1. `h ≤ 0`：落地；
2. `m ≤ 0.001·m0`：质量下限（视为烧毁/空爆收尾）；
3. `step ≥ 500 000`：步数保护（防极浅角度长时间不收敛）。

**能量账**（v3.0 采用「初末差」口径，保证闭合）：

```
E_total = E0 + m0·g0·H_atm        （H_atm = 200 km，重力势能也计入）
E_ground = ½·m_term·v_term²
E_atm = E_total − E_ground
E_drag = Σ ½ρv³C_D A·dt           （阻力做功，单独记）
E_ablated = max(E_atm − E_drag, 0)（烧蚀质量带走的动能）
```

这样 `E_atm + E_ground ≡ E_total`，误差只来自浮点。代价是：`E_atm` 是反推值，不能反过来验证积分器本身的误差；`E_drag` 与 `E_atm` 在极端工况下可能不自洽（被 `max` 截断）。

**地面插值**：最后一步跨过 h=0 时，用最后一个采样点与终态做线性插值，得到 t/v/m 的地面值，避免采样间隔造成的落地误差。

### 4.4 空爆 / 地撞判定（`breakup.py`）

| 条件 | 模式 | 释放能量（驱动坑/冲击波/热辐射/等级） | 地面耦合系数 |
|---|---|---|---|
| 落地且触发解体 | 地表撞击（碎片云） | E_ground | 1.0 |
| 落地且未解体 | 地表撞击（完整硬撞击） | E_ground | 1.0 |
| 未落地且触发解体 | 空爆（通古斯模式） | E_atm | 0.85 |
| 未落地且未解体 | 大气烧毁 | 0 | 0.0 |

- **当量按模式取不同口径**：地撞只算真正落到地面的动能，避免把大气中已释放的能量重复计入地面毁伤；空爆直接取大气总沉积。事件总能量 `E_atm + E_ground` 在 `trajectory.energy_distribution` 里单独展示；
- 60 m 通古斯量级空爆约 16–30 Mt；
- 100 m 这种「99% 能量在大气、1% 落地」的工况，Hero 卡显示的是落地当量（约 0.77 Mt）而不是事件总能量——这是刻意的取舍，代价见 9.1 末尾的「当量口径」说明；
- 空爆高度取「能量沉积峰值高度」（`energy_peak_h_km`），比解体触发高度更接近真实爆点；
- 穿透比 `mass_per_area / 1e4 kg/m²` 用于解释「为什么公里级天体必然落地」。

### 4.5 撞击坑（`crater.py`）

Collins et al. (2005) 简化式：

```
D_t = 1.161 · (ρ_i/ρ_t)^(1/3) · L_eff^0.78 · v_impact^0.44 · (sinθ)^(1/3)
D_final = 1.25 · D_t          （重力塌陷修正）
```

- `L_eff = D · (m_term/m0)^(1/3)`：用落地剩余质量反推等效直径（烧蚀后变小）；
- `v_impact`：落地速度（`terminal.v_kms`），不是入射速度；
- `sinθ`：真实入射角（角度钳制 ≥5°，sinθ 下限 1e-3 防极浅角除零）；
- 空爆/烧毁模式直接返回 0（无实体坑）。

### 4.6 冲击波（`shockwave.py`）

Sachs 缩放，点源地面爆炸：

```
W = E_release · η_ground / 4.184e6      （kg TNT）
r = Z · W^(1/3)                          （m，转换为 km）
Z = 2 / 3 / 8                            （20 / 10 / 1 psi）
```

| 区域 | 超压 | 典型破坏 |
|---|---|---|
| 核心区 | 20 psi ≈ 138 kPa | 地面汽化、建筑完全摧毁 |
| 次级区 | 10 psi ≈ 69 kPa | 建筑坍塌、林木焚毁 |
| 外围区 | 1 psi ≈ 6.9 kPa | 玻璃震碎、轻度损毁 |

上限：核心 500 km、次级 1500 km、外围 5000 km（硬截断，见第 9 节）。

### 4.7 热辐射（`thermal.py`）

**火球半径**：

```
r_fireball = min(0.0023 · E^(1/3), 100 km)
```

**三度烧伤半径**：按通量阈值解方程（v3.0 新模型）：

```
F(r) = η·E·exp(−r/L) / (4πr²) = F_th
η = 0.35     能量中转化为热辐射的份额
L = 40 km    大气衰减特征长度
F_th = 4.184e5 J/m²（10 cal/cm²，三度烧伤阈值）
```

二分求解 r，上限 2000 km。近距离退化为 `sqrt(ηE/4πF)`，远距离因指数衰减自然饱和——避免纯 `sqrt(E)` 在 Gt 级把烧伤半径放大到几千公里。

### 4.8 等级与观测点（`classify.py`）

**灾害等级**（纯能量口径，与模板库 L1–L5 一致）：

| 等级 | 释放当量（吨 TNT） |
|---|---|
| L1 微型撞击 | < 1e6 |
| L2 小型灾害 | 1e6 – 1e9 |
| L3 中型灾难 | 1e9 – 1e12 |
| L4 大型灾变 | 1e12 – 1e14 |
| L5 灭绝级撞击 | ≥ 1e14 |

**观测点**：

1. 在核心区 → 地面汽化；
2. 在次级区 → 建筑坍塌；
3. 其余距离分别判断「外围区（冲击波）」与「烧伤区（热辐射）」，**两个效应合并输出**（如「外围区…；同时热辐射烧伤区…」），避免烧伤半径较大时把外围区永久遮蔽。

### 4.9 编排器（`simulation.py`）

只做三件事：参数归一化（target 固定陆地）、按顺序调用物理模块、组装返回 dict。不含物理公式，便于替换单模块。

## 5. 服务层（`appV2.0.py`）

### 5.1 路由

| 路由 | 方法 | 作用 |
|---|---|---|
| `/` | GET | 返回前端页面 |
| `/api/simulate` | POST | 跑一次模拟，返回完整 result |
| `/api/ai/narrative` | POST | 动态场景叙事（模板填充） |
| `/api/ai/fun-refs` | POST | 趣味能量对标 |
| `/api/ai/parse-command` | POST | 自然语言 → 参数 |
| `/api/ai/qa` | POST | 关键词科学问答 |
| `/api/ai/disaster` | POST | 完整灾害分析报告 |
| `/api/db-info` | GET | 模板库统计 |

参数校验：材质白名单、直径 5–50000 m、速度 1–100 km/s、角度 5–90°，非法返回 400。

### 5.2 模板库

`data/impact_templates_v1.json`，共 **132 条**，结构：

```
rule_id, level(L1–L5), impact_type(airburst/surface),
material(ice/rock/iron), target(land/ocean), angle_group(G1/G2/G3/null),
e_min, e_max, disaster_title,
main_text, angle_desc, airburst_only, surface_only,
land_extra, ocean_extra, visual_cue, warning_note
```

匹配键：`(level, impact_type, material, target, angle_group)`

- `level` 由释放当量查表（与 classify 同一套阈值）；
- `impact_type`：模式字符串含「地表撞击」→ surface，否则 airburst；
- `angle_group`：<30° G1、30–60° G2、≥60° G3；L1/L5 不分角度（null）；
- v3.0 强制 `target=land`，所以 66 条 `ocean` 模板目前不可达（见第 9 节）。

### 5.3 插槽（slot）

模板里的 `{{xxx}}` 由 `build_slot_values()` 填充：

| 插槽 | 含义 |
|---|---|
| `diameter` / `velocity` / `angle` | 输入参数（直径单位为**米**） |
| `final_tnt` | 释放当量（带单位，如「3.08 十亿吨」） |
| `remain_mass_ratio` / `ablation_ratio_pct` | 剩余/烧蚀质量比 |
| `breakup_altitude` | 空爆高度（取能量峰值高度） |
| `fireball_r` / `burn_r` | 火球、烧伤半径 |
| `blast_core_r` / `blast_outer_r` | 冲击波核心/外围半径 |
| `crater_r` | 坑半径（km） |
| `seismic_magnitude` | 等效震级 `(log10E−4.8)/1.5` |

### 5.4 文本生成

- **叙事**：`main_text + airburst_only/surface_only + land_extra + 能量对标 + visual_cue`；
- **灾害报告**：等级 + 能量 + 坑径 + 四个半径 + 模板正文 + 适用场景；
- **问答**：按关键词（坑/能量/范围/等级）返回对应字段；
- **自然语言解析**：先解析速度（要求「每秒」语义），再直径、角度、材质，最后套「通古斯/希克苏鲁伯/小/大」预设。

## 6. 前端（`templates/index.html`）

单文件，约 1 800 行，无构建、无框架。

**布局**：全屏 canvas 作背景；左上输入面板；右上结果面板（Hero 卡 + 2×2 指标 + 烧蚀卡 + 模式卡 + 能量换算 + 灾害范围 + 等级）；底部动画控制条。

**渲染管线**（每帧 `draw()`）：

```
清屏 → 相机变换（平移/缩放）→ 星空 → 地球 → 城市标记 → 坑
→ 大气分层 → 等高线 → 轨迹 → 陨石 → 粒子/冲击波/碎片
→ 爆炸 → 伤害范围 → HUD（不受相机变换）
```

**动画**：用 `trajectory.samples` 做时间轴，`meteorPathPos(h)` 把高度映射到屏幕轨迹上的位置；播放/暂停/重置/时间滑块/倍速；爆炸粒子、冲击波环、烟柱、地震裂纹都是程序化生成。

**数据流**：点击「运行模拟」→ `fetch('/api/simulate')` → `renderResults()` 填 DOM → `setupAnimation()` 用 samples 建时间轴。

## 8. 公式速查

```
质量          m = (4/3)πr³ρ
动能          E = ½mv²
TNT           1 t TNT = 4.184×10⁹ J
重力          g(h) = g0·(R/(R+h))²
密度          ρ(h) = ρ_b·exp(−(h−h_b)/H)
阻力          a = ½ρv²C_D A/m
烧蚀          dm/dt = −½ρv³C_H A/Q_abl
动压          q = ½ρv²
解体          q ≥ σ → A ×5（单次）
地下/大气能量  E_atm = (E0 + m0 g H_atm) − ½m_term v_term²
坑径          D = 1.25·1.161·(ρi/ρt)^(1/3)·L^0.78·v^0.44·(sinθ)^(1/3)
冲击波        r = Z·W^(1/3)
火球          r = 0.0023·E^(1/3)
烧伤          ηE·e^(−r/L)/(4πr²) = 4.184×10⁵
震级          M = (log10E − 4.8)/1.5
```

## 9. 可优化空间与不足

### 9.1 物理模型

1. **单块体 + 单次 pancake**：真实解体是碎片级联，碎片云的阻力/烧蚀面积随时间增长；当前只放大一次面积，会低估解体后的减速与烧蚀。
2. **质量下限 0.1%**：既是性能保护，也直接决定「空爆 vs 地撞」的判定边界（100 m 岩石只剩 1.8% 质量落地，就判成地撞）。建议改成绝对阈值 + 让质量自然趋零。
3. **烧蚀参数标定**：`Q_abl = 5 MJ/kg` 低于硅酸盐汽化热（8–14 MJ/kg），`C_H = 0.1` 也偏经验；两者共同决定「多少质量能落地」，建议用 Chelyabinsk / Tunguska 数据反标定。
4. **烧蚀硬截止 3 km/s**：真实暗飞行由热流决定，速度阈值会在 3 km/s 处产生质量曲线拐点。
5. **能量账用初末差反推**：闭合好看，但掩盖了积分器误差；建议保留「阻力做功 + ½v²|dm|」的逐步积分作为独立校验，两者偏差超过 5% 时告警。
6. **热辐射经验参数**：η、L 是拍定值，没有按高度/波长/云量分层；Gt 级结果仍偏大（5000 m 天体约 390 km 烧伤半径）。
7. **冲击波点源假设**：空爆高度、地形遮挡、大气分层折射都没建模；上限硬截断让 L5 级别失去区分度。
8. **坑径未用地形/靶材分层**：`impact_energy_j` 参数目前未使用；Collins 公式对 <12° 的极浅角另有修正，未实现。
9. **等级只看能量**：50 km 低速天体和 100 m 高速天体可能同级；建议加入「直径下限」或「能量 + 直径」二维分档。
10. **无海洋/海啸**：v2.1.1 有 `tsunami.py`，v3.0 删除后 66 条海洋模板变成死代码。

> **关于当量口径的取舍**：地撞模式用落地动能驱动坑/冲击波/热辐射，空爆模式用大气沉积。
> 好处是不把同一份能量重复计入地面毁伤；代价是「大气中释放了 99%」的碎片云工况，
> Hero 卡只显示落地当量（100 m：0.77 Mt，而事件总能量 75.8 Mt）。
> 更完整的做法是 Hero 显示事件总能量、毁伤模型用落地动能，两个字段分开，
> 而不是共用一个 `release.energy_j`。

### 9.2 数值方法

11. **前向欧拉 + 固定 dt=0.01**：高阻阶段（低空、大面质比）变化剧烈，建议自适应步长（按 ρvA/m 缩放）或 RK4。
12. **解体瞬间面积阶跃**：×5 的突变会让该步的阻力/烧蚀出现尖峰，可用 2–3 步平滑过渡。
13. **地面插值基于最后采样点**（0.5 s 前），跨地面速度变化大时有 1% 量级误差。
14. **终止条件产生「假终态」**：质量下限退出时仍有 7–8 km/s 速度，`terminal.v_kms` 不是真实落地速度。

### 9.3 工程

15. **双实现分叉**：`demo.html` 与 Python v3.0 各改各的，已经出现坑径、观测点、文案不一致；建议以 Python 为单一事实源，用脚本生成 JS，或至少共享一份 `constants/formulas.json`。
16. **无自动化测试**：目前靠手工脚本回归（能量闭合、288 组扫描）；建议补 pytest + 数值基准（Tunguska 60 m、Chelyabinsk 19 m、Chicxulub 10 km）。
17. **模板库无 schema 校验**：132 条里 66 条 ocean 不可达，占位符曾出现未定义键；建议加 JSON Schema + 覆盖率测试（每个 rule_id 至少能被一组参数命中）。
18. **前端 1 800 行单文件**：无模块化、无构建；动画与物理在同一线程，极端参数下掉帧。可拆组件、把物理放 Web Worker。
19. **Web 服务**：`debug=True`、单进程、无缓存/限流；生产部署需换 WSGI。
20. **参数范围不一致**：前端滑杆 5–5 000 m，API 允许 50 000 m；建议统一并在 UI 上标注。

### 9.4 产品/内容

21. **叙事是模板拼接**：不是生成式 AI，长文本会有重复感；模板单位/措辞需要持续校对。
22. **缺少对比与导出**：不能并排比较两次模拟，也不能导出报告/图片（canvas 可 `toDataURL`，加个按钮即可）。
23. **观测点是单点**：没有方位、地形、建筑类型；「安全区」结论过于绝对。
24. **无历史/分享链接**：参数不能编码进 URL，复现一次模拟要手动重填。

## 11. 如果要继续做，建议的顺序

1. **统一双实现**（把 demo.html 的坑径/观测点/模板同步到 Python 口径，或反过来）；
2. **质量下限与烧蚀标定**（决定空爆/地撞边界，影响最大）；
3. **自适应步长 + 能量双账校验**（把数值可信度坐实）；
4. **模板库治理**（删/恢复海洋模板、schema、覆盖率测试）；
5. **产品化**（对比、导出、分享链接、移动端——demo.html 已做过一版响应式，可移植）。
